# تشغيل النسخة المدمجة

## النطاق

النسخة المدمجة تحافظ على واجهة Market Tower كاملة، وتضيف ثلاث وحدات مستقلة: محرك الإشارات الموحد، سجل صحة الاستراتيجية، وتقارير يومية وأسبوعية وشهرية. كما أضيف عامل Node يعمل دون الحاجة إلى فتح المتصفح، ويستخدم نوافذ UTC مدتها ثلاث ساعات لتسجيل إشارة واحدة لكل نافذة، وبحد أقصى ثماني إشارات في اليوم.

## الأسرار

لا تضع المفاتيح داخل HTML أو JavaScript. بعد تحويل المستودع إلى خاص، أضف الأسرار التالية من إعدادات المستودع في GitHub Actions: `TWELVE_DATA_KEY` و`NEWS_API_KEY` و`TELEGRAM_BOT_TOKEN` و`TELEGRAM_CHAT_ID`. إذا استُخدمت مصادر إضافية في طبقة مستقبلية، أضف `FINNHUB_KEY` و`FRED_KEY` بالطريقة نفسها. يجب تدوير رمز Telegram القديم قبل إضافته.

## الجدولة

الملف `.github/workflows/oracle-schedule.yml` يحدد تشغيل الإشارة عند الدقيقة صفر من كل ثلاث ساعات UTC، والتقرير اليومي عند 00:05 UTC، والأسبوعي عند 00:10 UTC يوم الأحد، والشهري عند 00:15 UTC في اليوم الأول من الشهر. يمكن تشغيل أي وضع يدوياً من تبويب Actions عبر `workflow_dispatch`.

GitHub Actions خدمة جدولة وليست عقدة تشغيل دائمة؛ قد يحدث تأخير في الجدولة أو توقف مؤقت بسبب حدود المنصة. إذا كان شرط 24/7 يعني مراقبة مستمرة دون تأخير، يُنقل العامل نفسه لاحقاً إلى خدمة دائمة، مع إبقاء المستودع وملفات التقارير في GitHub. لا ينبغي استخدام GitHub Actions لتنفيذ أوامر تداول مباشرة.

## التتبع والتقارير

كل سجل يتضمن وقت الإنشاء، النافذة الزمنية، الزوج، الاتجاه، درجة الثقة، نقطة الدخول، وقف الخسارة، الهدف، الأسباب، ومصدر البيانات. لا تُحسب صحة الاستراتيجية إلا بعد إغلاق الإشارة وفق وقف الخسارة أو الهدف أو انتهاء مدة الاحتفاظ. يعرض النظام معدل الفوز المرصود، مجموع النقاط، وعدداً تقديرياً مستقبلياً باستخدام متوسط لاحق Bayesian posterior mean لتجنب اعتبار عينات صغيرة حقيقة مؤكدة. هذا التقدير ليس ضماناً ولا توصية استثمارية.

## التحقق قبل التفعيل

شغّل العامل يدوياً أولاً بعد إضافة الأسرار، افحص رسالة Telegram، راجع `data/signals.json`، ثم شغّل تقريراً يدوياً لكل فترة. بعد ذلك راقب أول 24 ساعة في تبويب Actions، وتحقق من عدم تكرار `slot` ومن تسجيل الإشارات المغلقة قبل الاعتماد على التقارير.
